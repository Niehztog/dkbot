# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this project is

dkbot adds multiplayer bots to Daikatana 1.3 by loading our own game module into the stock, closed-source engine -- no engine source, no patched binaries. The bot AI is Mr. Elusive's Gladiator Bot for Quake II, built from the `gladiator-bot-restored/` submodule. Everything known about the engine comes from the official `-dbgsyms` packages and disassembly; `docs/ARCHITECTURE.md` and `docs/LOADER.md` have the details.

## How the module gets in

- Daikatana is a Quake II fork: `usercmd_t` is Quake II's, `edict_s` keeps Quake II's shared header, and `game_import_t`/`game_export_t` are supersets of Quake II's.
- The world module talks to the engine through `serverState_t` (`gstate`, handed over by `dll_Entry` message 12). Anything aimed at clients goes through it, not `gi`.
- 1.3 links the retail game DLLs statically but keeps the plumbing: `DLL_LoadDLLs` `dlopen(NULL)`s the executable, and `DLL_FindFunction` returns the first `dlsym` hit in its `dll_t dlls[50]` table. Our module takes slot 0 -- on Linux the `LD_PRELOAD` shim interposes `dlopen`, on Windows `dkbot.dll` hooks the executable's `GetProcAddress` import -- so the 17 `dll_*` names we define win and everything else falls through to the engine.
- `GetGameAPI` fills `globals` after `DLL_LoadDLLs` returns: never patch `globals` from `dll_Entry`.
- `GetGameAPI` copies `gi` and `serverState` afresh at every server start (the first map, a map after `disconnect` or `killserver`; not a map change): a slot patched in either goes in again at every message 12 (`DK_HOOK` in `dkbot/cmd.c`).
- The game registers most client commands (`kill`, `use`) from `dll_ServerLoad` inside the original `dll_Entry`: a hook on `AddCommand` goes in before that call.
- Loading our module `RTLD_GLOBAL` can add names the engine resolves (new entity classes), never replace one the executable defines.
- Paks and BSPs are not Quake II's (72-byte pak entries, compressed; IBSP v41): use `tools/dkpak.py` and `tools/dkbsp.py`, never a stock reader.

## Rules

### ABI

- **Never guess the ABI.** Every struct, offset and prototype comes from the shipped DWARF (`vendor/*/dbgsyms/*.dbg`, `llvm-dwarfdump-18`; follow a typedef to its defining DIE) or from disassembly. Mark anything else as an open question.
- Re-run `make check-boundary` and `make check-pdb` against every new upstream build. The launcher warns on every Windows build but the one `SUPPORTED_BUILD` names. A new offset macro needs a fact in `tools/check-pdb.py`, which fails on one it does not know.
- The Windows ABI differs wherever a struct holds a path (`MAX_PATH` is 260 there, 4096 on Linux), and `unsigned long` is 32 bits. `include/dk/dk_boundary.h` carries both layouts.
- Verify hand-written mangled names against `nm -D`: `dk_sym` returns NULL for a typo, and the feature silently disappears.
- Never probe a cvar with `gi.cvar()`: it creates the cvar, and an empty `teamplay` aborts the game. Use `Cvar_VariableString`/`Cvar_VariableValue`.
- `absmin`/`absmax` are the link box, one unit larger per side. Take box constants from `PM_CheckDuck`.

### Bots in the engine

- The library adds `delta_angles` to its view at every update: pass it each change once, as `bl_main.c` does by clearing them.
- Synthesize usercmds exactly as `gladiator-bot-restored/game/bl_main.c` does: angles relative to `delta_angles`, Quake II's right vector for `sidemove`, +-400 moves, `msec = 1000 * thinktime`, and `ClientThink` called twice with half the `msec`.
- Bots hold real client slots (`cs_spawned`), allocated from `maxclients` down. `dkbot/clientbuf.c` re-arms each slot every frame, because `SV_InitGame` reallocates `svs.clients`: message buffers, `lastmessage` and `idletime` against the timeout and idle kicks, qport -1, and on a listen server a 0.0.0.0 netchan address, so that bot packets never enter the host's loopback ring.
- Never swallow a per-client send. Senders stage into a shared buffer that only the real call empties, so a dropped call hands its message to the next recipient.
- `ge->ClientDisconnect` is our `dll_ClientDisconnect`, which forgets a bot the engine drops (a kick): disconnect a bot only through `disconnect()` in `dkbot/bots.c`.
- Tables indexed by client number hold `DK_MAX_CLIENTS` (256), the engine's ceiling for `maxclients`.
- Never spawn several bots in one frame: spawn-point selection puts them all on one point.
- `player_record_t.deaths` is never written by the engine. Respawn needs a button transition, not a held button.
- The `bot` command is registered with `Cmd_AddCommand`, which clients cannot reach; only the console and rcon can. It needs no permission check.
- The game registers `say` only on a listen server, so bots chat only there: chat, and the spam kick it can earn (`docs/ENGINE-BUGS.md`), never show on `dkded`.
- The model index table handed to the library is the engine's own: `sv.configstrings` from `CS_MODELS`.

### The bot library

- `gladiator-bot-restored/` is read-only. Change behaviour by copying a TU into `botlib_patch/` (upstream plus `dkbot:`-marked blocks) or data into `botdata/`. Moving the pin means a three-way merge per fork and the checks in `botlib_patch/README.md`.
- The library reads each map through the engine's `FS_LoadFile` (`gstate`) and converts it in memory (`botlib_patch/dk_maps.c`); that conversion and `tools/dkbsp.py convert`'s must stay byte-identical.
- Game-specific knowledge goes into the AI (`botlib_patch/be_ai2_dmdk.c`, forked from `be_ai2_dmq2.c`), not into values `dkbot/` forges for Quake II logic. Facts cross the boundary through `include/dk/dk_entstate.h` (`modelindex2`, `stats` 20..23) and libvars.
- `GLAD_SERVERFIX=1` is the default. A refreshed fork keeps upstream's `#if GLAD_SERVERFIX` blocks, or the flag stops reaching them.
- The library is linked `-Bsymbolic`, because the engine exports its globals; without it the library's `ctf`, `logfile` and the like bind to the engine's.
- Keep `-ftrivial-auto-var-init=zero`. `make botlib AUTOINIT=pattern` checks for a new uninitialized read.
- "Nothing hit" in a trace is `ent = 0`; any other sentinel floods the library with errors.
- Read contents with `AAS_PointContents`, never `AAS_PointPresenceType`, which returns an area's presence type. Grep the forks for both names when the pin moves.
- Write presence types by name, `PRESENCE_NORMAL` (2) and `PRESENCE_CROUCH` (4). The 1999 `AAS_PresenceTypeBoundingBox` swaps their boxes, which `GLAD_SERVERFIX(aas-presence-bbox-swapped)` undoes; without it the library's traces are blind above a bot's knees.
- A bare numeric Quake II inventory index in the AI reads zero here, and is a bug until proven otherwise. Our indices start at `DK_ITEM_BASE` (80), clear of the library's hardcoded slots.
- The generated `inv.h` must carry the library's own 200+ slots, or `BotSetupClient` fails and bots run without a character. Check the log for `BotSetupClient(...) -> 1 (ok)`.
- Weapon reach is not `weapons.json`'s range (`reach()` in `tools/gen-botcfg.py`).
- Level items are matched by classname and by model. Deathmatch's spawnflag is 0x8000, not Quake II's 0x800 (the `notspawnflags` libvar).
- Item configs carry each pickup's engine box (`tools/gen-botcfg.py`). The library finds an item's area through it, and with Quake II's +-16 box an item the engine rests on the floor (all ammo, the Megashield) gets none and is never a goal.
- `EA_UseItem` weapon switches are fire-and-forget; `dkbot/bots.c` reconciles them.
- Never switch away from the Daikatana while `playerHook_t.fxFrameFunc` is set: the sword's pending frame function then writes past the next weapon's block and corrupts the engine's heap (`docs/ENGINE-BUGS.md`).
- Most doors, buttons and the health stations work only with the use key (`docs/ARCHITECTURE.md`): face the target and press when the engine's own use trace would hit it, and never hold use, since only a fresh press counts.
- Players rest 1/8 above floors, exactly the AAS trace's `TRACEPLANE_EPSILON`: an AAS trace down from a standing bot must not read as starting in solid (`botlib_patch/be_aas_sample.c`), or `AAS_OnGround` fails and the ground travel code never runs.
- Links into traps, ladders up into crouch-only areas and teleporter links from them are no route for a bot; `DK_ForbidFatalJumps` retypes them at load, the traps before the fatal jumps. So are links through a `func_explosive`, which BSPC never compiles, and links that brush a teleporter landing in a trap.
- A bot in an area with no route back into the game kills itself after 10 s without an enemy (`DK_AreaTrapped`): judge a map's self-kills with that in mind.
- Gladiator's AI never reads sounds, so none are forwarded.
- Daikatana calls its five attributes skills, while binary names say `*_boost`: use "skill" in our names and prose.

### Navigation data

- Always BSPC 1.4 (`bspc.exe` under wine), unpatched, on an x86 host: under box86 it compiles different geometry than on x86 or Windows. `tools/dkbsp.py` marks Daikatana's player-solid bits 0x80 and 0x200 solid (ladders excepted), and turns water carrying 0x800 into lava.
- BSPC compiles `tools/dkbsp.py bspc`'s output, never `convert`'s: BSPC splits space only along brush sides it finds a face for, and Daikatana's maps lack many, so walkable space would turn solid. `bspc` adds those faces and flags not-in-deathmatch entities with Quake II's 0x800 (`docs/AAS.md`).
- `aas/` carries the reachability the library computed when the files were made: a change to how links are built (`be_aas_reach.c`, the AAS sampling and movement code) leaves them stale until each map's reachability is recomputed from BSPC's raw output, which is deterministic and needs no bot.
- Bots standing where they spawned mean the library cannot drive them: a missing config or `.aas`, which the console names. A bot wedged in one spot is usually the navigation data; check `area=<n>/<reachabilities>` in the status line.

### Running and measuring

- Runtime tests use the real `dkded` through `tools/run-dkded.sh` (under box64 on a non-x86-64 host, where `BOX64_LD_PRELOAD` is the emulated process's `LD_PRELOAD`). The run directory needs real copies of the binaries, since the engine finds `data/` through `/proc/self/exe`; `vendor/gamedata/` holds the game's `data/` tree, copied from an install.
- Never restart a server someone is connected to. Put experiments on their own `DK_PORT` (the engine also opens `port - 10`), and kill by port: `pgrep -af '[d]kded.*<port>'`, never a bare `pkill`.
- Measure with `tools/bench.py` over paired seeds, ten or more, on a map with the hazard and one without; a change to how bots fight also needs mixed games. A bot that waits never tries to move: its idle column shows what a stuck count misses. `gib_enable 0` keeps runs reproducible, and bench sets it.
- `DK_BOT_GIVE="weapon_give_4"` arms each bot as it spawns (needs `cheats 1`). `docs/DEBUGGING.md` lists the engine's own tooling.
- A fault in `calloc` or a heap abort is an earlier write past a heap block: preload `build/gmalloc.so` to make that write fault (`docs/DEBUGGING.md`).

### Repository

- Quake III Arena is a reference, never a source: it is GPL, and this tree cannot take GPL code (`NOTICE.md`).
- Never write into or build from a sibling `../gladiator-bot-restored/` checkout; `GLAD=<dir>` only on purpose.
- `vendor/` (~150 MB of upstream binaries) stays out of git.
- Keep comments and docs minimal: a one-line comment only where the code cannot say it, and no history or measurements in code or docs.
- Prefer editing over rewriting; read before writing; no fluff in output.
